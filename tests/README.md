# Tests

All tests run against a local Nutshell mint with a fake Lightning backend (no real money):

```
pip install cashu
MINT_BACKEND_BOLT11_SAT=FakeWallet MINT_PRIVATE_KEY=test MINT_DATABASE=./data/mint FAKEWALLET_BRR=TRUE MINT_INPUT_FEE_PPK=0 \
  python3 -m cashu.mint --port 3338 --host 127.0.0.1
```

On Python 3.13, `pip install cashu` (0.21.0) needs a hand: install its dependencies with `breez-sdk-spark==0.18.0`, `limits<4` and `marshmallow<4`, a `coincurve` 21 wheel, then `bip32` and `cashu` with `--no-deps`.

- `library_test.mjs` — the flow with cashu-ts only (`npm i @cashu/cashu-ts && node tests/library_test.mjs`).
- `browser_test.mjs` — the real page in Chromium, three parties with separate storage (`python3 -m http.server 8080 --directory app`, then `node tests/browser_test.mjs`; needs `playwright` and a `tokens.json` with two plain tokens from the local mint, see the top of the file).
- `status_test.mjs` — the status page: four real donations through `index.html` (one released, one left locked, one refunded, one left past its deadline) and one forged ledger entry, then `status.html` must report each from the mint alone. Then, in the donor's own browser, the page must list those four donations by itself and turn them into ledgers that read back the same. Same server as above; it mints its own fake ecash.
- `lightning_test.mjs` — donating with Lightning: the mint check on a new campaign, an invoice paid and minted straight into the lock, a reload between payment and minting (the mint call is blocked, then the page reloads), the mint's answer lost after it minted (the page gets the ecash back with NUT-09 restore), a link with a bad deadline, release with its answer lost (restored at once; and once more with restore blocked too, finished when the page is reopened), a refund paid to a Lightning invoice, a too-large invoice refused before anything moves, and a closed campaign. The fake Lightning backend pays the mint's own invoices, so no wallet is needed.

- `keys_test.mjs` — keys are never lost: a clinic that makes a new key after donations were locked to the old one still certifies them (the old key is kept); a browser holding another clinic key says which keys the token is locked to and does not sign; importing an export keeps the keys that browser had; the Streetcat tab of a browser without the Streetcat key stops before asking the mint; a plain token is refused with a clear message; and a new key that cannot be saved changes nothing.

- `release_test.mjs` — Streetcat releases only what the clinic really certified: a token with one proof unsigned ("Partly signed (2 of 3) — not certified") or signed with another key ("Signed with a key that is not MOCHI's clinic key") is refused before anything is sent to the mint; a part the donor already took back after the deadline is left out of the release; the clinic can still certify after the deadline, with a warning; and the status page counts each proof once, however many ledger entries list it (a part of a donation, the donation, and its certified copy). Once certified or released, the button says so in its screen's colour ("✓ Certified" in the clinic's blue, "✓ Released" in Streetcat's green) and cannot be pressed again, and the page buzzes (counted through `navigator.vibrate`); "release another token" empties the box and brings the button back; the same token pasted again says "✓ Already released" before anything is pressed, with no swap sent.
- `offline_test.mjs` — certifying without coverage: the clinic opens the app once with a connection, then its server is switched off and the browser goes offline. The app must still open from its service worker (`app/sw.js`), with its font, read the donation with the mint's keys kept from last time, and certify it ("Signed without a connection"); back online, Streetcat releases it. The cat recognition, got ahead of time with Offline setup's button (without starting it), must load offline from the phone and give, for a drawn photo, the numbers Streetcat's phone gives; a donor's phone, which never asked for it, must keep none of its 48 MB.
- `core_test.mjs` — `app/core.js` in Node with the app's own cashu-ts bundle (no browser): keys derived from a campaign key, DON- codes, packing for link/file/relay (and a link that would expand without end), the request (with the cat's photos as caught, and what is not a valid list of them: four, a slot twice, a bad SHA-256, one too big; their parts, which rebuild each photo and name the clinic's key) and the clinic's answer with every way it can be wrong (one proof unsigned, another key, a declaration changed afterwards or for another request, a signed report), a release where one proof is split and its rest goes back under the same lock, the donor finding that rest with NUT-09 restore and taking it back after the deadline, the ledger v2 with the clinic's declaration, and a volunteer's acknowledgment. Run it with `MINT=http://127.0.0.1:3339` too (fees are paid out of Streetcat's part; the rest stays exact).
- `relay_test.mjs` — `app/relay.js` (requests and answers by Nostr relay) against three local test relays from `nostr_relay.mjs` (one refuses every event); needs Node 22 and `npm i ws` (for the test relays only), no mint. Streetcat sends a request and two relays confirm it; the clinic receives it once; its receipt and certified answer come back; a request or an answer from a key that is not the campaign's is dropped, and so is a message for another clinic; with every relay down the message waits in the outbox and goes out when they are back; and the relays hold nothing readable (no cat, campaign, spending key or proof, and every wrap is signed by a throwaway key).
- `relay_live_test.mjs` — the same layer against real public relays (the default list in `app/relay.js`, or `RELAYS=wss://…,wss://…`). Needs only Node 22 and four files of `app/`: `node tests/relay_live_test.mjs`. It checks each relay alone (takes a gift-wrapped event and gives it back), then the whole round, and passes if the round works through at least two relays. Not run from the build container (it cannot reach public relays). Passed on 5 Nov 2026 from StreetCat's Mac, on his home network: the round took 23.2 s; alone, 3 of the 5 relays then listed worked (`wss://nos.lol`, `wss://relay.primal.net`, `wss://nostr.mom`) and the request came through all three; `wss://relay.damus.io` and `wss://relay.0xchat.com` gave "could not connect" from that network. The default list in `app/relay.js` is now those three.
- `ledger_test.mjs` — the published ledger, version 2, on `status.html`: one donation pays 1500 of its 2100 sat for a spay (split: the rest goes back under its lock), another pays all of its 21. The page must count each part from the mint (the rest found with NUT-09 restore), show each donation's DON- code and what it paid for, accept the clinic's signed declaration and refuse an altered one, find a donation by its code, and add up the same from a version 1 ledger (from the mint alone). `SHOT=file.png` saves the page at 390 px. The rest is found the same way on Minibits (cdk-mintd 0.17.7, active sat keyset `01fc0ec0e59cd6fa…3c3a821`), checked on 5 Nov 2026: a NUT-09 restore of outputs it never signed answered HTTP 200 `{"outputs":[],"signatures":[]}`, with amount 0 and with amount 1, so a rest that is not there reads as "not found", not as an error.
- `publish_test.mjs` — Streetcat's ledger, made by the app: a campaign, two donations, one certified and released; Home's "copy ledger" gives a version 2 ledger with both by their DON- codes (the released one with what it released, no key anywhere), and `status.html` reads it back.
- `layout_test.mjs` — nothing is wider than the phone: every tab of every role (empty), and the status page, at 320, 375, 390 and 430 px (same server as above). It names any screen that sticks out, by how many pixels and its widest element. Then seven phones in Chromium's mobile emulation (which reads the viewport meta tag as phones do), from the first SE (320 × 460 visible) to the Pro Max (430 × 740): `app/fit.js` lays every page out 390 px wide, a little wider on a short screen, and the browser scales it to the phone, so each one shows what an iPhone 14–16 shows; opened from a signed campaign link with an amount chosen, Donate must not scroll on any of them (5 Nov: it fits on all seven, with 13 to 139 px to spare).
- `requests_test.mjs` — requests without pasting a token: the app in Chromium against the local mint and three local test relays from `nostr_relay.mjs` (one refuses every event; the app is pointed at them with `localStorage['vetlock.relays']`). A donor locks 2100 and 21 sat and sends each to Streetcat from the app; Streetcat's campaign lists both, checked against the campaign (lock and DLEQ). A request pays 1500 sat of the first and all of the second; the clinic finds it under "To review", cannot confirm before ticking the box, confirms while offline (the answer waits under "Waiting to be sent", goes out when the connection is back, then "Done"); Streetcat checks every proof and the declaration and releases, and the 600 sat not needed go back under the same lock (found again from the donor's own token with `traceDonation`). A second request travels only as a link: the clinic reports "postponed", Streetcat reads the signed report from the answer link and cannot release; a phone with another clinic key cannot confirm. The clinic adds the vet's invoice to the first: only its SHA-256 goes into the signed declaration (the file name and bytes appear nowhere), the ledger carries the clinic's declarations, and `status.html` shows the fingerprint where a declaration has one ("no receipt fingerprint" where it has none) and checks a picked file against it in the browser: the invoice matches, a changed copy does not. A third goes in person with the clinic offline: the request is an animated QR on Streetcat's screen and the answer one on the clinic's; it pays 100 sat of the 600 left, which is split again (500 back under the lock). The published ledger has the parts and the rests, and `status.html` counts them from the mint. The filled screens are checked at 320, 375, 390 and 430 px. Also run on the fee mint (`MINT=http://127.0.0.1:3339`): there the lock itself costs 1 sat, so the rests are 599 and 499 sat.
- `handover_test.mjs` — in person, against the local mint and two local test relays: the donor's app shows a locked donation as an animated QR (numbered parts, changing by itself); the QR on screen decodes back with the app's own `jsqr.min.js`. A volunteer, with a key of their own and no Streetcat key, collects the parts out of order and gets four checks (mint signature by DLEQ, the campaign's conditions, duplicates, spending state at the mint), accepts and shows a signed acknowledgment labelled "Not a certification", which the donor's app reads back from the volunteer's screen, verifies and keeps (an altered one does not verify). The same donation again is "Already received" and cannot be accepted; one received offline says its spending state was not checked. Forwarded by relay, both appear in Streetcat's campaign as "in person". The card is a 1080 × 1350 PNG with no text chunk, and a token typed as its message is refused. Then the real scanner: Chromium's fake camera plays the donation's QR parts from a Y4M file (written to `$TMPDIR`, removed after) and the app reads them all. Nothing is loaded from outside the app, the mint and the relays (the price feed is answered by the test). Filled screens checked at 320–430 px. Also run on the fee mint.
- `signed_test.mjs` — campaigns signed by Streetcat (local mint, no relay). A new campaign's link carries a BIP-340 signature; the donor's page says "signed by Streetcat" and takes the donation. A link with its clinic key or its deadline changed says its signature does not match, greys out the payment and makes no call to the mint (no swap, no invoice); a field the signature does not cover is dropped. An unsigned link, as every link made before, opens with a plain notice, plus a warning when its mint is not Streetcat's (Minibits), and still takes donations. The app pins Streetcat's published key (`STREETCAT_KEYS`, one line in `app/core.js`), and the test checks it is exactly that key; the test pins its own Streetcat key next to it by hand. A link naming any other key, signed with that key (a valid signature) or not signed, says in red "This link is not from Streetcat's published key. Do not donate through it.", never "signed by Streetcat", greys out the payment and makes no call to the mint; Streetcat's own page will not make such a campaign. Home signs a campaign made before when the browser holds its Streetcat key, and a browser without the key cannot make a campaign for it. `SHOT_DIR=dir` saves the donor's view of a signed, an unsigned, a broken and an unpublished-key link (`sg1`–`sg4`).
- `ledger_nostr_test.mjs` — the ledger published by Nostr, against the local mint and two local test relays (made-up keys; nothing goes to a public relay). Home's "publish ledger" sends the campaign's ledger v2 as one replaceable event (kind 30078, `d` = the campaign's id, a hash of its name, mint, keys and deadline), signed with the ledger key derived from the campaign's Streetcat key, and the status link carries `n=<id>`. `status.html` fetches the newest event, checks its signer and its campaign, and counts every donation at the mint. Newer events under the same id signed by another key, or naming another campaign, are ignored. Publishing again replaces the ledger. With no relay it falls back to `l=` (the ledger's file), and says so; with neither, that the ledger was not found.
- `wallet_test.mjs` — paying from a Cashu wallet (NUT-18, experimental), against the local mint and two local test relays. The donor's page shows a plain payment request (`creqA`: unit sat, the campaign's mint only, no lock in it, a description naming the campaign, single use) with a Nostr transport (NIP-17) to an nprofile: a key made for this donation and kept with it, and the app's relays (the nprofile encoding is checked against NIP-19's example). A "wallet" in Node pays it as cashu.me does, with the NUT-18 payload in a NIP-17 message. Plain ecash is locked on arrival into the campaign's lock with the refund key kept for that request, and the wallet's ecash is spent at the mint. A payment made while the page was closed is picked up when it opens again. Ecash already locked to other keys (as a wallet applying only a lock's main key would make) is refused with the reason, and the request stays open; ecash already carrying exactly the campaign's lock is taken as it is; a token pasted by hand is locked the same way; ecash from another mint is not taken.
- `csp_test.mjs` — the browser security policy in `app/vercel.json`. The pages are served by the test's own static server on port 8090 with the headers Vercel sends (plus, for this test only, the local mint and relays in `connect-src`), and every screen of every role is opened, a donation locked, its card drawn, the scanner loaded and the service worker registered, and the status page checks a donation at the mint, while every `securitypolicyviolation` is recorded: none is allowed. It also checks that the pages keep no inline script or inline event handler (their code is in `app/index.js` and `app/status.js`, so the policy needs no hashes), that `vercel.json` carries every directive as decided, and that an inline script injected into the page does not run. The cat recognition runs under the policy too (its worker, the WebAssembly and both models, on a photo drawn in the page): it needs `'wasm-unsafe-eval'`, and `'unsafe-eval'` stays out; used once, the service worker has kept its files. Served without that word, its worker's WebAssembly is refused, so the policy is in force inside the worker as well (a worker gets the policy sent with its own file). That refusal is wanted and not counted: it is told apart by its worker (`catid-worker.js?strict`), not by time, since the console can report it a moment after its check (once, under load, it was counted against the next one).
- `receipt_test.mjs` — the donor's private recovery receipt, version 1 (no relay). After locking, "save private receipt" asks for a download of a PNG named for the donation ("download requested"); the donor ticks the box and confirms ("confirmed"); opening the saved file checks it ("Backup verified"). The PNG has one `tEXt` chunk (`streetcat.recovery-receipt`) with the JSON version 1 (format, version, created, campaign, donation with its code, amount, keyset and token, refund key) and a check (the first 16 hex of the SHA-256 of the rest, canonical), and every text the page draws is recorded: the private key never is. A screenshot of it (the picture without its data), an edited copy and another donation's receipt are refused, each with its reason. With a password (10 characters or more) the key is sealed (PBKDF2-SHA256, AES-GCM) and is in the file in no form; opening it needs the password. In a browser that never had the key (time zone Europe/Madrid), "Take my sats back" reads the file: what the receipt says and, apart, what the mint says, the refund date in UTC and local time, "Refund not available yet", and the most that can come back by Lightning or as ecash. A receipt made before version 1 (JSON) still opens, "no integrity check".
- `refund_test.mjs` — refunds read from receipts in browsers that never held their keys: a campaign whose deadline is 40 s away (keys made here), four donations. Before the deadline, "Refund not available yet" with the date in UTC and local time, and taking it back is refused. Streetcat and the clinic release one donation whole and 1 500 sat of another, as the app does. After the deadline: "Released"; one taken back as ecash, then "Refund completed" (and "Already refunded" in another browser); the split one's rest (600 sat) found with `traceDonation` and paid to a Lightning address on a local LNURL-pay test server, whose invoice is paid; an invoice for more than there is refused before anything moves, with the exact most and a button to copy it; and a Lightning refund whose answers are lost (the mint pays, the page never hears) shows "Refund in progress · Do not pay or claim again", refuses to pay again, and "check now" finds it paid ("Refund completed"), with the melt log kept from the start. Also run on the fee mint.
- `audit_test.mjs` — regression tests for the independent audit of 5 Nov (refund-v1 at c165a23). a01: a link signed with an attacker's own keys is refused in red on the donor's page by every route (ecash, Lightning, a Cashu wallet) with no call to the mint, and its ledger is flagged on the status page. a07 b: the status page checks a ledger's campaign (red for a broken signature, an unsigned campaign or a key that is not Streetcat's published one; "✓ campaign signed by Streetcat" otherwise) and says what comes from the mint and what from Streetcat's ledger. a09: a donation released whole is flagged in red unless the clinic's signed declarations cover what the mint shows released, with or without parts in the ledger, and a release declared in full is not. F5: the clinic will not sign a token locked with SIG_ALL, with two refund signatures or with no refund key, and the status page does not count a SIG_ALL lock.
- `payout_test.mjs` — what Streetcat releases goes straight to its Lightning address (set once in Home), against the local mint and a local Lightning address server (LUD-16) whose invoices are the local mint's. Home checks the address when it is saved: one that answers HTTP 404 is said in red, something that is not an address is not saved, one that takes payments says "✓ Every release is paid at once to …". A release is then paid out at once, the most the mint can pay after its fees, its invoice is paid, and nothing of it stays in this browser but any unused fee; when the mint's answer about the payment is lost (the request goes through, the page never hears), the page asks the mint, says it was sent, and pays nothing twice; an address that does not answer keeps the released ecash here, said in red, with its copy button. Home counts only what is still in this browser. Also run on the fee mint.
- `cats_test.mjs` — the cat's record, against the local mint and one local test relay. In Node: a record signed with the clinic's statement key checks out (name trimmed, microchip without spaces); an edited one, one naming another clinic key and a microchip of 14 digits do not; a photo goes in parts of at most 26 000 characters that rebuild it, and a part that is not one (wrong kind, too long, not base64, out of range, an unknown slot) is refused. In the app: the clinic opens Streetcat's request for MOCHI, whose screen names the record still to make; the form opens with the cat, the procedure and the date of the request in one line ("edit" opens them), coat and notes folded, and a photo tile asks for the camera (`capture="environment"`); filled in, it fits in one screen of an iPhone 14–16 (390 × 844). Four photos as a phone takes them (the face 3000 × 2250, about 7 MB, with an EXIF block carrying a made-up GPS label) are each made small on the phone: JPEG, at most 38 kB and 640 px, none of the camera's data left. A microchip of 14 digits is said in red and nothing is signed; with 15 the record is signed ("✓ Signed", not pressable again) and goes: the record through the outbox, its photos in 8 parts straight to the relay, every message under 56 kB. Streetcat, whose campaign names the clinic, checks for new records and lists MOCHI with ✓ (signed by its campaign's clinic, every photo there), finds it by name, chip digits, colony or coat, and shows its four photos, its microchip and "✓ Signed by the clinic of TNR MARINA: every photo is the one it signed." The clinic's list says "sent", and so does the request. The clinic's file carries the record and its photos; from a file, an edited record is refused in red, a swapped photo is not kept ("photos: 3 of 4 here"), and a record signed by a clinic of none of the campaigns is listed as "unknown clinic", in red, and not trusted. "Record another cat" brings back an empty form with the colony kept. The three screens fit at 320–430 px.
- `catid_test.mjs` — "Already in the records?" on the clinic's new record (no mint, no relay; about a minute, most of it the first load of the 48 MB from the local server). The photos are drawn in the page, six patterns, each drawn as the views of its record and once more, moved and turned, as the new photo: no real photo is kept with the tests. With no records nothing is offered and nothing is fetched. With five records, a new photo makes it ask first ("…your 5 records… The cat recognition comes once: 48 MB."), with nothing fetched yet. On a tap it shows the megabytes coming and the records' photos compared one by one, then three tiles, the drawn cat's own record first with its photo, and "Only an order, not a match". Every photo was worked out once (13 kept). A tile opens that record, and ← comes back to the new one with its photo and the tiles. A second photo works out only that one. A new record starts clean, and its photo is compared with no second tap. A cat with no record gets the same words. Nothing goes to another address, and it fits at 390 and 320 px. With one record, then two, it says so ("Your only record", "Your 2 records, the most alike first"). If a model cannot come, it says so in red with the button to try again, and the tap works once it can.
- `reqphotos_test.mjs` — the cat's photos in Streetcat's request, against the local mint and two local test relays; the photos are drawn in the page, no real photo is kept with the tests. The new request offers three (face, sides), optional; taken, the line says how many and how big. The request names them by SHA-256 and they go by relay, in parts ("its 3 photos sent"); Streetcat's request shows them. The clinic gets the request and the three photos whole (each the one its SHA-256 says) and the line "Check it is this cat"; a tap shows one big, a second small again. In person, by QR, with the clinic offline, the request comes without them ("3 of 3 on their way"); with a connection they arrive by relay and a ticked box stays ticked. A request saved as a file carries them, and another phone sees them at once. Every screen with photos fits at 320, 375, 390 and 430 px. Run it with `MINT=http://127.0.0.1:3339` too.
- `header_test.mjs` — the header and the clinic's home, against the local mint (for the requests). A first visit opens on Donate, with no "Who are you?" screen and no block of text; the header shows Donor, Rescue, Clinic and Status, the role on screen marked, in one line (also with the back arrow, framed, 36 × 36); Status is the magnifier icon, labelled Status, with no text; a role in the header switches to it, the role on screen goes back to its first screen, and the role is kept for the next visit; a campaign link opens Donate after another role; `?role=` shows only that role. The clinic's home with three requests: six buttons of one size, full width, one under another, all inside 390 × 844 with two requests listed (with a third the page scrolls only a little), Offline setup right after Certify a token and red while the phone is not ready, each opening its screen. Back: the phone's back from Certify a token returns to the clinic's home on the same page, the header's ← from Settings does too, and so does the phone's back after Cat records. - `hues_test.mjs` — the colours of TnR and Tnr2 (no mint). Made before links carried their colour, they now have fixed ones, as StreetCat chose: TnR 345 (pink) and Tnr2 100 (yellow), by name and deadline (1793923199), on the app and the status page, in a fresh browser and in one whose colour registry held others for them. No new campaign, and none without its own colour, is ever given 345 or 100; a campaign whose own signed link carries one keeps it.
- `settings_test.mjs` — the clinic's settings and "Ready for offline" (no mint needed). The key backup is refused for a password under 10 characters or two different ones; the file holds the public key and no private key in any form (PBKDF2-SHA256, 310 000 rounds, AES-GCM); on a phone that never had the key, a wrong password or a damaged file changes nothing, and the right one brings back the same key and the older one kept with it. With the service worker allowed, the checklist first says what is missing, then "Ready for offline use ✓" once the app has saved itself (scanner and relay code included) and the key is there; not being installed is a warning; the clinic's home shows the same state. The cat recognition there: a warning until it is saved, with its button, never "not ready"; a tap shows the megabytes come (0 → 48), then ✓, the button goes, and its four files are whole in the copy the service worker reads (`streetcat-ai-1`); with one model unreachable it says so in red and keeps the button, and the next tap goes on from what was kept (14 → 48).

To use an installed Chrome instead of Playwright's own browser: `CHROME=/usr/bin/google-chrome node tests/…`.

Every error, warning and odd state must be red, in the app's bad colour (`var(--bad)`). `tests/colors.mjs` (installed by `pin.mjs` in every browser suite) records each visible line that reads as one, with its colour; with `COLORS_DIR=dir` each suite writes what it saw there, and `colors_test.mjs`, run after the suites with the same `COLORS_DIR`, fails on any that was not red and lists them all.

Streetcat's published key is pinned in `app/core.js` (both pages use it), so the tests, which make Streetcat keys of their own, load the pages through `tests/pin.mjs`: the one `STREETCAT_KEYS` line of `core.js` is served with the test's keys added after the published key (the file is not changed). Every Streetcat key a test's page makes or imports is pinned at once in all its pages; a key made in Node is pinned with `pin(pk)`. `csp_test.mjs` serves `core.js` the same way from its own server, so its service worker gets that file too.

The receipt is no longer on the donor's screen as text, so the tests take it as its file carries it, from the page's test hook `__vetlock.receiptOf(lockedToken)` (it reads what the browser already keeps).

`SHOT_DIR=dir` makes `requests_test.mjs`, `handover_test.mjs`, `settings_test.mjs`, `catid_test.mjs` and `reqphotos_test.mjs` save each filled screen there, at 390 px @2x (`r1-…`, `h1-…`, `s1-…`, `like-…`, `q1-…`).

Fees: `lightning_test.mjs` and `status_test.mjs` also run against a mint that charges input fees. Start a second mint with `MINT_INPUT_FEE_PPK=100` (its own `MINT_DATABASE`, `--port 3339`) and run them with `MINT=http://127.0.0.1:3339`. Passed on 4 Nov: amounts drop by the fee at each swap (21 locked → 20 released; 13 refunded as 12 → 10 to the invoice + 1 back) and every step still goes through.
