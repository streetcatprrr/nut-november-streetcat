# Certified donations in ecash

**Streetcat's entry for Nut November 2026.** Donations in Cashu ecash that nobody can spend, the charity included, until a veterinary clinic confirms that the work was done. If it never is, the donor takes the sats back after a deadline.

**Where it stands (19 Nov).**

- **With real sats, on a public mint:** a donation locked, confirmed with the clinic's key, released, and read back as released by the public status page (Minibits; test keys).
- **With fake money only:** `dest`, a rule for the mint that says where locked ecash may go. It is written up as a [NUT-style proposal](docs/dest-lock.md) with [worked examples](docs/dest-vectors.md), and needs a patched mint.
- **Checked by:** 88 test suites that drive the real pages, 84 of them run as a whole before each release (the other four are run apart), and several security reviews whose findings, and what was done about each, are in [Progress](#progress).
- **Tried apart, not in the app:** a zero-knowledge proof that lets a `dest` payment stay blinded ([`zk/`](zk/README.md)). It runs against a test mint; its setup is not fit for real use and nobody has reviewed its circuit.
- **Not yet:** a real cat's sterilisation paid this way, and a refund after its deadline with real sats at a mint that runs CDK (with fake money it has run at a public test mint that runs CDK).

## In two minutes

**The problem.** A charity publishes its receipts after the money has moved. Here the money cannot move until the receipt exists.

**What is built.** Three apps, one for each role, built from one static codebase ([`app/`](app/)) with no server of its own: they talk to a Cashu mint and to Nostr relays, and every key stays in the browser.

| Who | Does what |
|---|---|
| **Donor** | pays a Lightning invoice from any wallet; the page mints the ecash already locked, and keeps the key that refunds it |
| **Rescue** (Streetcat) | makes campaigns, asks a partner to confirm a piece of work, releases what was confirmed |
| **Partner** (a clinic) | reads each request and confirms it with its own key, or reports a problem |
| **Anyone** | the status page asks the mint what became of every donation, and takes nobody's word for it |

**Two locks.**

1. **Today's lock** works at any mint with NUT-11: two signatures (Streetcat and the clinic), and the donor's refund key after the deadline. Since 15 Nov its signatures cover the whole transaction (`SIG_ALL`): the clinic signs exactly what leaves the lock and what goes back under it. That has run with fake money at a stock Nutshell 0.21.0, and with real sats on a public mint that runs other software (Minibits, cdk-mintd; 16–17 Nov, in a test copy of the app with test keys): donated, confirmed, released, and read back as released on the status page.
2. **The new one, `dest`, is an experiment** ([`docs/dest-lock.md`](docs/dest-lock.md), written in the form of a NUT; worked examples in [`docs/dest-vectors.md`](docs/dest-vectors.md)). NUT-11 says who must sign; it cannot say where the value may go, so two signers who agree can send it anywhere. `dest` is one tag and a rule for the mint: locked ecash can only be paid to the keys the lock names, or stay under its lock, or go back to the donor after the deadline. The clinic is then paid by the mint itself. Streetcat orders each payment and can never hold the money. It needs a patched mint ([`mint/`](mint/), a patch on Nutshell 0.21.0), nobody outside this project has reviewed it, and it has only run with fake money.

**See it run.** A test mint with the rule is up at `https://mint.streetcat.org` (fake money, as it says of itself; 20 Nov). No mint with real sats has the rule, so the quickest proof is still the test suite, which drives the real pages in Chromium against local mints with fake money:

```
# the patched test mint on port 3340: four commands in mint/README.md
python3 -m http.server 8080 --directory app &
node tests/destflow_test.mjs    # a donation locked, confirmed, and paid to the clinic by the mint, through the three apps
node tests/dest_test.mjs        # the rule itself: every spend it must refuse, with the mint's own reason
node tests/fuzz_test.mjs        # random spends, each judged against a model of the rule
```

There are 88 suites ([`tests/README.md`](tests/README.md) says what each one covers and what it does not). To put a test mint with the rule on a server of your own: `sudo bash mint/install.sh mint.example.org`.

**What to be sceptical about.** The `dest` rule is new and unreviewed. The mint is trusted with the funds, as in all of Cashu. A clinic can still sign for work it did not do: the lock moves that trust from the charity to the clinic, it does not remove it. Each of these is spelled out below, with what the reviews so far found and how each finding was dealt with.

## Why

[Streetcat](https://streetcat.org) is a registered non-profit in Spain that feeds feral colonies, pays vet bills and runs trap-neuter-return. A sterilisation costs 40–80 €; a street cat eats 70–100 g of food a day. We publish receipts for everything, but a receipt is published *after* the money moved. Cashu lets us turn that around: **the money cannot move until the receipt exists.**

## How it works

Today's lock uses spending conditions that already exist in the protocol ([NUT-11](https://github.com/cashubtc/nuts/blob/main/11.md) P2PK, [NUT-14](https://github.com/cashubtc/nuts/blob/main/14.md) HTLC). No mint has to change anything.

1. **Donate.** The donor pays a **Lightning invoice from any wallet** — no Cashu wallet needed — and the page (client-side, using cashu-ts) mints the ecash straight into locked proofs ([NUT-04](https://github.com/cashubtc/nuts/blob/main/04.md) + NUT-11): the ecash is never made unlocked. (Between the payment and the minting, whoever holds the mint's quote id could mint it; it is kept in this browser only, and the app does not yet lock quotes to a key, NUT-20.) The donation link is signed with Streetcat's key, so a link someone changed (another clinic key, another deadline) is refused before any money moves, and so is a link with no signature (anyone could take it off). Donors who already hold ecash on the campaign's mint can paste it instead, and the page swaps it into the same lock:
   - spendable only with **two signatures: Streetcat + the clinic** (`n_sigs = 2`), and
   - after a deadline (`locktime`), **also** spendable by the **donor's refund key** alone (a new key for every donation).
   The donor keeps the locked token, and the page sends it to Streetcat's campaign by itself (Nostr relay, end-to-end encrypted). Nobody can spend it yet. If the phone switches to the wallet app and the page reloads, the paid invoice is picked up again on return.
2. **Operate.** The cat is sterilised. Streetcat pays the clinic **in euros**, as always. The clinic's role is to attest, not to receive sats.
3. **Certify.** Streetcat sends the clinic a request — which cat, which procedure, and how much of which donations pays for it — by Nostr relay (end-to-end encrypted), or as a link, a file or a QR. The clinic reviews each request on its own and confirms it with a key it published once (on its own website or printed on its invoices), or reports a problem. Its answer signs exactly the transaction the request describes for each donation (for a donation made before 15 Nov, each of its proofs), plus a declaration that names them.
4. **Release.** Streetcat checks every signature and the declaration, adds its own, and the mint accepts the swap. The sats go to Streetcat's reserve; what a split donation does not need goes back under the same lock, still the donor's to take back after the deadline. Anyone can check that the released token carried the clinic's signature.
5. **Or refund.** No certification before the deadline → the donor takes the sats back with the refund key, as ecash or paid straight to a Lightning invoice or address. The key travels in the donor's private receipt: a picture of the donation that carries its data inside (never drawn), checked once saved, optionally protected with a password. Whatever part of a donation was not released (the rest of a split one too) can be taken back. Under NUT-11 the two-signature path stays open after the deadline too (we checked Nutshell 0.22.1 and CDK 0.17.7, and a local test confirms it), so a late certification could still win the race; the clinic's screen warns when the refund date has passed, and whatever the mint settles first counts.
6. **Follow it.** The campaign's [status page](app/status.html) — its ledger published by Streetcat on Nostr, or as a file — lists every locked donation and asks the mint what happened to each one: still locked, released with the clinic's signature, or refunded. It takes nobody's word for a donation's state, Streetcat's included (it does trust the mint for every state, and whoever published the ledger for which donations there are; a ledger that is not the signed one on the relays is said to be nobody's word): the lock is read from the token, the mint's DLEQ proof (NUT-12) shows the ecash is real, and the signatures the mint returns for spent ecash (NUT-07) show who signed (for a donation signed whole, over the transaction its witness gives back).

Variant for clinics that do not want a key: the clinic generates a secret code before the operation and hands over only its hash; donations are locked to that hash (HTLC) plus Streetcat's signature; the code is printed on the invoice when the operation is done.

### What it guarantees, and what it does not

- Guaranteed by the mint: the sats can only move with the clinic's signature (plus Streetcat's), or back to the donor once the deadline has passed.
- Not guaranteed: that the clinic signs honestly. That is the same trust as today's invoice — but now the clinic, not the charity, is the one who vouches.
- Not guaranteed either: that the second key is a clinic's. It is the key Streetcat signed into the campaign; a donor who wants to be sure checks it against what the clinic itself publishes (its website, its invoices). The test campaign kept in `app/campaigns/` uses a key of Streetcat's own in that place.
- How far a certification reaches. Every donation made since 15 Nov is locked signed whole (NUT-11 `SIG_ALL`): the clinic's signature covers the whole transaction, every proof's secret and `C` and every output's amount and blinded message. It spends no proof but the ones the clinic was shown, and sends nothing where the clinic did not see: the payment to Streetcat's reserve, the amount confirmed less the mint's fee, and the rest of the one proof a release splits, back under the same lock in outputs worked out from that proof, where its donor finds it with the token alone. The mint refuses anything else, a changed Rescue app keeping that rest included (`tests/wholelock_test.mjs`). Each donation is one transaction, since each has its own refund key. The status page and the donor's app read who signed each spend from the text its witness gives back, where the mint keeps it (Nutshell). A mint that keeps of a witness the signatures alone (cdk-mintd) gets the witness NUT-11 writes, and the text of each spend travels in Streetcat's ledger beside the part it paid: the status page checks it against the mint's signatures, and a text other than the one signed proves nothing. A refund made by another wallet, or at such a mint, whose record holds only the signature, is shown as spent and not as released; the donor's own app knows it took it back.
- Donations made before 15 Nov keep the lock they were made with (`SIG_INPUTS`), and its limits: the clinic's signature covers each proof's secret and nothing else. The scans of 14–15 Nov found what that allows (finding 2.2, reproduced here): a mint signs any number of proofs with one secret, so whoever knows a donation's secret (the ledger publishes it) can have a 1-sat proof made with it, and the clinic's signature on that proof, checked and confirmed for 1 sat, spends the real one. And what one certification can release is the value of the proofs it signs, so a changed Rescue app could keep the rest of a split proof. A request of such a donation may name no more proofs than paying it needs (what they hold beyond the payment is less than the largest of them), and donations are cut small (no proof over a tenth of the donation).
- A known limit of both (audit of 10 Nov): whoever has a donation's token, which the ledger publishes, can work out the outputs the rest of a split proof goes back in, and have the mint sign them first, for a sat each; a release that splits that proof is then refused (nothing moves, the proof can still be released whole, and the app says what happened). The experimental lock of 10 Nov (below) does not have this.
- What the clinic signs is what it was shown: before it can confirm, its app checks every proof's amount against the mint's own signature (the DLEQ proof of NUT-12, which every request carries) and, for a donation signed whole, that what the request leaves for the mint is the mint's own fee. That check trusts the mint the campaign names.
- Keys: the clinic's declarations, the relay messages and the ledger are signed with keys derived from the campaign keys (k + t, with t public), so a campaign needs no new keys announced. They keep apart what each signs, not who could spend: whoever learns a derived private key learns the spending key too. So none of them ever leaves the app: worked out when needed, never exported, shown or logged. (The spending keys themselves are kept in the browser's storage, and their holder can show and export them, in Keys.)
- Trust in the mint: it holds the bitcoin and enforces the lock. It cannot forge the clinic's signature, but it could lose or keep the sats, and nothing here proves its reserves. Fine for small donations held for a few weeks; not for large sums.
- Honest wording for donors: *your sats do not pay the vet bill; we pay it in euros. Your sats are released to Streetcat only when the clinic certifies the operation, and you get them back if it never happens.*

## Prototype

`prototype/vetlock_proto.py` starts a local [Nutshell](https://github.com/cashubtc/nutshell) mint with a fake Lightning backend (no real money), creates three wallets (donor, Streetcat, clinic) and runs the whole flow. Verified output in `prototype/run-2026-11-04.log`:

| Scenario | Mint says |
|---|---|
| Streetcat tries to spend without the clinic's code | `no HTLC preimage provided` |
| Streetcat with a wrong code + signature | `HTLC preimage does not match` |
| Streetcat with the clinic's code + signature | **accepted** |
| Donor refund before the deadline | refused |
| Donor refund after the deadline (3 s lock) | **accepted** |
| Two-signature lock, Streetcat alone | `signatures (1) present for n_sigs (2)` |
| Two-signature lock, Streetcat + clinic | **accepted** |

Run it: `pip install cashu && python3 prototype/vetlock_proto.py` (Python ≥ 3.10).

### Wallet and mint support (from the [NUTs compatibility table](https://cashubtc.github.io/nuts/))

| | P2PK (NUT-11) | HTLC (NUT-14) |
|---|---|---|
| Nutshell, cdk, cashu-ts | yes | yes |
| Minibits, Cashu.me, Sovran | yes | no |
| Macadamia | no | no |
| Mints: Nutshell, cdk-mintd, nutmix | yes | yes |

Donors never need special wallet support: any Lightning wallet pays the invoice (or they send plain ecash), and the donation page does the locking; releases and refunds also go through the project's pages.
